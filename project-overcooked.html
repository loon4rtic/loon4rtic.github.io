01

Overview

A networked co-op cooking game built with Unity Netcode and inspired by Overcooked. Players share a kitchen and have to coordinate to prepare and serve incoming orders.

The brief

Create a multiplayer game in Unity using Netcode, with at least three unique gameplay features.

02

Key features

Networked co-op

Multiple players share the same kitchen in real time using Unity Netcode.

Orders & assembly

Order tickets list each recipe, and players chop and assemble ingredients at kitchen counters to fill them.

Emote system

Quick "Hello", "Nice" and "Help" emotes let teammates communicate without voice chat.

Floor trap

A hole opens in the floor, sending players back to one side of the map and swallowing any item that falls in.

03

My role

This was a solo project, so I programmed all five systems below myself. Every one is server-authoritative: clients ask, the server decides, and the result is broadcast to everyone, so all players always see the same kitchen.

01

Networked interaction: pick up, drop and throw

Two players can never grab the same item at once, because every interaction follows the same pattern: request, validate, then broadcast.

  1. RequestThe client calls SetKitchenObjectParent(), which fires SetKitchenObjectParentServerRpc.
  2. ValidateThe server finds the new parent across the network with a NetworkObjectReference and calls TrySetParent().
  3. BroadcastUpdateParentLogicClientRpc updates the item on every client.

Dropping and throwing reuse the same pattern to take an item out of a player's hands and back into physics. The server calls TryRemoveParent(), then a ClientRpc re-enables gravity and colliders on every client at the same moment, so the item lands in the same spot for everyone.

02

Food assembly counters

Specialised counters where players get ingredients, chop them, cook them and assemble them.

  • Spawning: SpawnKitchenObjectServerRpc creates the ingredient on the server and immediately parents it to the requesting player's NetworkObject.
  • Chopping: a manual process where players press Space. Progress is stored in a NetworkVariable<int> called cuttingProgress, and an RPC updates the progress bar on every client.
  • Cooking: an automatic, timed process. Only the server runs the timer, moving the item through idle, cooking and fried. It also despawns the raw meat and spawns the cooked version, which stops two clients from finishing the same cook at different times.
03

Collaborative plating and delivery

Players build meals together on plates and deliver them to fill randomly generated orders. The server validates every step, and ClientRpcs keep items and UI in sync for every player.

  • Plates: adding an ingredient calls AddIngredientServerRpc, and the server broadcasts the ingredient to every client by its name.
  • Orders: a server-side singleton generates random orders from a list of DeliveryRecipeSO ScriptableObjects.
  • Delivery: the delivery counter checks the plate's ingredients against the active orders on the server.
04

Floor trap

A hole in the floor that respawns players at one side of the map and despawns any item that falls in.

  • The server runs TrapRoutine, which shows and hides the floor through a NetworkVariable so it stays in sync for every client.
  • The kill zone collision is checked on the server, so clients can't accidentally respawn themselves.
05

Emotes

Players pick from preset messages to talk to their teammates. The Emote Manager UI runs only on the local client and safely gets the local player's NetworkObject to start the request.

  1. RequestThe client sends the message to the server with PlayEmoteServerRpc.
  2. ReceiveThe server receives the message.
  3. BroadcastIt immediately sends it to every client with PlayEmoteClientRpc.

Problem

Working with Unity Netcode. It was my first time building a networked game, so concepts like RPCs, NetworkVariables and server authority were all new to me.

Solution

I learned through trial and error, testing each system as I built it, and by watching videos online.
