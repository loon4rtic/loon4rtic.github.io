01

Overview

ONE RUN is a strategy-based deckbuilder made in Unity. Players build a deck and fight through turn-based card battles across a single roguelike run, where every choice counts. It's published on itch.io and plays in the browser with just a mouse.

Player reception

Rated 4.7 out of 5 on itch.io in its first week, with players calling it "so addictive" and recommending it to fans of Inscryption.

02

Key features

Deckbuilding

Build and refine your deck as the run goes on, choosing which cards to take into each fight.

Turn-based combat

Strategic card battles where planning each turn matters more than reflexes.

One roguelike run

Every run is a fresh attempt, so each decision has lasting consequences.

Online leaderboard

One run a day, the same for everyone. Scores are saved to a LootLocker leaderboard so players can see how their run ranks.

My role

I was the main UI/UX designer on the team, responsible for how the game looks and feels to navigate, from the menus to the screens players use during a run. I also helped code and set up the online leaderboard, using LootLocker as the backend database so every player's score is saved and ranked against everyone else's. 04

UI design process

I mocked up every screen in Canva before it was built in Unity, then iterated on the layouts with the team. Each mockup is shown next to the screen that shipped. Placeholder text and repeated cards in the mockups are intentional: they're layout drafts, not final art. Click any image to see it full size.

Run over screen · Three views in one

Instead of sending players to separate pages, the run over screen has one default view and two toggles. The "Stats" and "Leaderboard" buttons expand the screen in place, so players never lose sight of their result.

Default view · Your result

The stops along the run as coloured tiles, with the stop you died at in red, then a score breakdown and the total. In the build, the breakdown grew to include clean fights, precise kills and handicaps.

Stats toggle · Where the run went

The top half compacts and a table opens underneath, showing each stop's enemy, turns against par, HP lost and score banked, so players can see exactly where their run fell apart.

Leaderboard toggle · How you rank

Since everyone plays the same run each day, how you rank matters as much as your score. The screen splits so the LootLocker leaderboard sits beside your result, with your own row highlighted and a field to set the name you post under.

Combat HUD · Grouping the turn controls

  1. Iteration 1First draft

    Banked score and turn count in the top corner, the hand along the bottom, the draw pile tucked under the player's HP, shield and energy, and a large text box beside the enemy.

  2. Iteration 2Layout pass

    I moved the draw pile to the right, under the End turn button, so the turn controls sit together. The text box shrank into a smaller info panel in the top right to open up the space around the enemy.

  3. In gameShipped

    The shipped HUD follows the second layout: draw and discard piles beside End turn, the player's health and energy bottom left, and the info panel in the top right now shows the enemy's next move, so players can plan around it.

From mockup to game · Every screen in the run

Title screen

The layout carried straight over: the card row, logo, today's date and seed. The build added Practice and Tutorial alongside Play, a leaderboard shortcut, and a line explaining that practice scores don't count.

Deck building

The card grid and "Your deck" panel shipped as planned. The build added filter tabs for each card type, and the detail box became a handicaps panel that shows how each one changes your score multiplier.

Run map

Shipped almost exactly as mocked up: eight stops, HP, gold, sales left and banked score. The build added the score each stop is worth, plus relics and items under your deck.

Shop

The tabbed layout, with a detail panel on the left and a grid on the right, made it into the game. Sales left and item slots moved up next to the title.

Between stops

The three-panel layout stayed, with categories on the left, choices in the middle and a summary on the right. The summary now previews your gold and HP before you commit.

Forge

Close to the mockup. The build added an instruction line, a scroll bar for larger decks, and a before-and-after label under each card so players can see what an upgrade does.

05

Biggest challenge

Problem

This was my first time designing UI, so I found it hard to know where things should go: which information players need to see at a glance, what can sit in a corner, and how to lay out a screen so it doesn't feel cluttered.

Solution

I studied the UI of other games, especially other deckbuilders, to understand how they place things like the hand, draw pile and card details. I used them as references for my Canva mockups, then refined the layouts from there.

06

Reflection

What I learned

ONE RUN was a good stepping stone for learning the basics of UI/UX. Going from blank Canva mockups to screens that shipped taught me how much placement affects how a game feels to play. It's something I want to keep getting better at, and I hope that further down the line I'll have a much stronger instinct for where each element belongs.
